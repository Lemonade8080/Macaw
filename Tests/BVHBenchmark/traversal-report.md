# 메시 피킹 탐색 최적화

측정일: 2026-09-29.

## 적용 내용

- 메시 BVH 노드를 로컬 AABB로 변경했다. 노드 크기는 56바이트에서 40바이트로 줄었다.
- Ray의 방향 역수와 평행 축 마스크를 호출당 한 번 계산하고, 모든 노드의 slab 검사에서 재사용한다. 평행 축은 나눗셈 전에 안전한 값으로 치환하고, 원점이 해당 slab 밖에 있는지 별도로 검사한다. 평행 판정 임계값은 기존 DirectX의 `g_RayEpsilon`을 유지한다.
- 탐색 스택은 지역 배열 64칸을 사용하며, 초과 시에만 동적 배열에 저장한다. 먼 자식만 push하고 가까운 자식은 바로 탐색한다.
- 월드 피킹에서 이미 찾은 최근접 거리를 컴포넌트와 메시 BVH까지 전달한다. 컴포넌트에서 로컬 Ray 정규화 배율을 적용하고, 로컬 한계의 반올림으로 후보가 잘리지 않도록 상향 여유를 준다. 최종 거리는 월드 한계로 다시 검사한다.
- 최대 거리는 포함 경계이며 음수·NaN은 실패한다. 기존 호출자는 기본 인수를 통해 이전처럼 거리 제한 없이 호출할 수 있다. 실패 시 출력 거리는 변경하지 않는다.

## 비교 조건

- 기준은 이번 수정 직전의 partition 빌더 + OBB/동적 스택 순회다. `traversal-baseline.h/.cpp`에 보관했다.
- `Content/Prisoner_Capoeira.bin` 하나, 삼각형 12,128개. 6개 축 방향 카메라의 32×32 격자 중 루트 AABB를 통과하는 2,656개 Ray를 사용하며, 실제 메시 적중은 489개다.
- 기존과 변경 후 모두 32 bins, CT/CI 2.5. 동일 소스에서 추출한 빌더·순회를 같은 MSVC x64 `/O2 /MD /DNDEBUG` 실행 파일에 넣었다. DirectX 교차 검사와 엔진 TArray/Memory/Stat을 사용한다.
- 설정당 5회, 매회 Ray 배치 5번을 측정한다. 변경 전후 실행 순서를 번갈아 배치했다. 아래 시간은 배치 중앙값들의 중앙값이다. 측정 전 결과 검증으로 캐시가 데워진 조건이며 코어·클럭 고정은 하지 않았다.
- 빌드, 파일 로딩, 렌더링, 브로드페이즈, 컴포넌트 좌표 변환은 시간 측정에서 제외했다. 이 성능 표는 최대 거리 제한을 주지 않은 단일 메시 탐색 결과이므로, 월드 거리 전달의 추가 성능 효과는 포함하지 않는다.

## 결과

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| Ray당 중앙값 | 403.73 ns | 144.31 ns |
| 5회 중앙값 범위 | 396.23~420.14 ns | 142.77~159.45 ns |
| 5개 Ray 배치의 엔진 힙 할당 횟수 | 20,915 | 0 |
| 노드 크기 | 56 bytes | 40 bytes |

이 사례에서 탐색 시간은 약 64.3% 감소했고 처리율은 약 2.80배다. 모든 변경을 함께 비교한 결과이므로 개별 최적화의 기여도를 분리한 수치는 아니다. 단일 메시 결과를 전체 에디터 피킹 시간이나 모든 메시의 개선율로 일반화하지 않는다.

## 검증

- 변경 전후 2,656개 Ray의 hit/최근접 거리가 일치했다. 거리 비교 허용 오차는 `1e-4 * (1 + abs(referenceDistance))`다.
- 같은 Ray에 0, 0.5, 5, 1000 및 기준 hit 거리의 한계를 적용하여 hit 판정과 거리를 확인했다. 실패 시 출력 거리가 유지되는지도 검사했다.
- 기준 Ray 65개는 전체 삼각형 순회 결과와 비교했다.
- 박스 경계, 박스 안에서 출발, 뒤를 향하는 Ray, 0 및 음수 0 방향 성분, 거의 평행한 방향, 음수·NaN 거리 한계를 검사했다.
- 실제 `UMeshComponent::RaycastMesh` 함수 본문을 추출해 실제 FTransform 구현과 함께 검사했다. 회전·이동 및 비균일/음수 스케일 세 조합에서 월드 거리 한계보다 앞뒤에 있는 교차를 확인했다.
- 대기 노드가 70개 쌓이는 인위적인 깊은 트리에서 64칸 초과 후 동적 스택으로 전환하고 마지막 후보의 교차를 정상적으로 찾는지 검사했다.
- Debug x64 전체 솔루션 빌드 및 Macaw.exe 링크가 성공했다. 실행 UI를 통한 수동 피킹은 확인하지 않았다.

## 재실행

저장소 루트의 PowerShell에서 `./Tests/BVHBenchmark/traversal-generate.ps1`을 실행한 뒤 `./Tests/BVHBenchmark/traversal-run.cmd`를 실행한다. 생성 스크립트는 코드와 측정용 컴포넌트를 추출하고 `traversal-hashes.json`에 소스 해시를 기록한다. CSV 원본은 `traversal-results.csv`다. 기준 스냅샷은 덮어쓰지 않는다.
