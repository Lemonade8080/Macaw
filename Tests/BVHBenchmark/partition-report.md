# 메시 BVH partition 변경 비교

측정일: 2026-09-29.

## 변경

`Asset/UMesh.cpp`의 빌더에서 삼각형 ID를 세 축의 동적 bin 배열에 저장하던 부분을 제거했다. bin에는 바운드와 개수만 유지하고, 분할이 확정되면 공용 `mIndexGroups` 구간에 `std::partition`을 적용한다. 재귀 호출은 시작 위치와 개수를 전달하고, 리프는 해당 구간을 그대로 참조한다. 기존 SAH 식, bin 좌표 계산, 바운드 여유분, 레이캐스트 코드는 유지했다.

## 조건

- 저장소에서 파일 크기가 가장 큰 메시 `Content/Prisoner_Capoeira.bin`, 삼각형 12,128개.
- 한 시나리오: 메시 주위 6개 축 방향 카메라의 32×32 격자 레이 중 루트 AABB를 통과하는 2,656개. 실제 메시 적중은 489개다. 이전 벤치마크의 camera 생성 함수를 재사용했다. surface 레이 세트는 측정하지 않았다.
- 기존 코드 스냅샷 `partition-baseline.h/.cpp`와 변경한 소스로부터 빌더·순회를 추출해 같은 실행 파일에 컴파일했다. 같은 DirectX 교차 검사와 엔진 TArray/Memory/Stat 구현을 사용한다. UMesh는 정점·인덱스만 제공하는 테스트용 구현이다.
- MSVC x64 `/O2 /MD /DNDEBUG`, 단일 스레드. 애셋 로딩, GPU, 월드 변환과 브로드페이즈는 측정에서 제외했다.
- 기존 32/2.5와 변경 후 16/2.5, 32/2.0, 32/2.5, 32/3.0, 64/2.5의 6개 설정만 비교했다. 설정마다 새 트리 5회, 총 30회 빌드하며 고정 시드 9182로 순서를 섞었다.
- 빌드는 5회 중앙값이다. 레이캐스트는 결과 검증 후 레이 세트를 5회 측정한 중앙값을 구하고, 각 빌드의 중앙값 5개를 다시 중앙값으로 집계했다. CPU 고정 클럭·코어 고정은 하지 않았다.

## 결과

| 방식 | Bins | CT/CI | 빌드 ms | Ray ns/개 | 노드 | 리프 |
|---|---:|---:|---:|---:|---:|---:|
| 기존 | 32 | 2.5 | 39.7424 | 396.91 | 6,547 | 3,274 |
| Partition | 32 | 2.5 | 18.4744 | 399.77 | 6,547 | 3,274 |
| Partition | 16 | 2.5 | 14.9825 | 404.14 | 6,555 | 3,278 |
| Partition | 32 | 2.0 | 20.9578 | 399.70 | 8,317 | 4,159 |
| Partition | 32 | 3.0 | 18.0335 | 412.69 | 5,555 | 2,778 |
| Partition | 64 | 2.5 | 26.0127 | 393.52 | 6,531 | 3,266 |

같은 설정에서 빌드 시간은 약 53.5% 감소했다(2.15배 속도). 레이캐스트 시간 차이는 +0.7%이며, 측정 범위가 겹쳐 성능 저하로 판단하지 않는다. 원본 5회 레이 중앙값 범위는 396.20~453.24 ns, 변경 후는 386.94~407.68 ns였다.

16 bins는 이 사례에서 빌드가 가장 빠르지만, 이번 검사는 단일 메시·카메라 분포에 한정된다. 제품 기본값은 기존 여러 메시 실험에서 사용하던 32 bins, CT/CI 2.5를 유지했다. 64 bins와 비용비 변경에서 기본값을 대체할 확실한 이득은 관찰하지 못했다.

## 검증

- 30개 빌드 모두 2,656개 레이의 hit 여부와 최근접 거리가 기존 방식과 일치했다. 거리 허용 오차는 `1e-4 * (1 + abs(referenceDistance))`다.
- 기준 결과 중 고르게 뽑은 레이 65개는 전체 삼각형 순회 결과와 일치했다.
- 모든 트리에서 leaf 구간 범위, 구간 중복, 삼각형 ID 누락·중복, 노드 연결·도달성을 검사했다.
- 변경 빌더의 빈 메시, 단일 삼각형, 동일 중심 중복 삼각형, 영면적 바운드, 잘못된 인덱스 개수·범위, 동일 객체 재빌드를 검사했다.
- Debug x64 빌드에서 Asset 모듈은 통과했다. 전체 솔루션은 이번 변경 전부터 수정 중이던 `World/Subsystem/UPickingSubsystem.h:28`의 `FWorldRaycastAccelerationStructure` 선언 순서 오류로 실패했다. 해당 작업 파일은 수정하지 않았다.

## 재실행

저장소 루트에서 `Tests\BVHBenchmark\partition-run.cmd`를 실행한다. 소스 추출·컴파일·비교를 수행하고 `partition-results.csv`를 갱신한다. 집계 표는 위 CSV의 설정별 중앙값이다. 측정 소스와 메시 해시는 `partition-hashes.json`에 보관했다. `partition-baseline.h/.cpp`는 비교 기준이므로 덮어쓰지 않는다.
